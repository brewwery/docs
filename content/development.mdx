# Development

## Requirements

- **macOS 14** or later
- **Xcode 16** or later, or a Swift 6 toolchain
- **Homebrew**, if you want the app to manage real packages — tests never need it

## Quick start

```bash
git clone https://github.com/brewwery/brewwery.git
cd brewwery
swift build          # compile
swift run Brewwery   # run the app
swift test           # run the test suites
```

To work in Xcode, open `Package.swift`.

## Commands

| Command | Description |
| --- | --- |
| `swift build` | Build the core library and the app |
| `swift run Brewwery` | Run the app without packaging |
| `swift test` | Core, app, and rendering tests; nothing touches your Homebrew |
| `Scripts/make-app.sh` | Build a universal `dist/Brewwery.app`, ad-hoc signed for local use |
| `Scripts/screenshots.sh` | Capture the website and docs screenshots in both themes |
| `Scripts/release.sh --sign "Developer ID Application: …"` | Build, sign, notarize, and package a release |

## Tests

| Suite | Covers | Real Homebrew |
| --- | --- | --- |
| `BrewweryCoreTests` | Parsers against recorded Homebrew output, validation, detection, streaming, process-group cancellation | No — a scripted `brew` stand-in |
| `BrewweryAppTests` | Operations and history, search debounce, table navigation and layout, every page rendered in both themes, accessibility checks | No |
| `BrewweryLiveTests` | Reads, install and uninstall, cancelling a real download, services, taps, custom path, offline failures | **Yes**, opt-in |

The live suite changes your Homebrew installation — it installs and removes small packages and a tap — so it only runs when you ask for it:

```bash
BREWWERY_LIVE=1 swift test --filter BrewweryLiveTests
```

To review every page after a UI change, render snapshots to a folder:

```bash
BREWWERY_SNAPSHOT_DIR=/tmp/brewwery-snapshots swift test --filter RenderingTests
```

## Screenshots

`Scripts/screenshots.sh` launches a debug build in demo mode against `Scripts/demo-brew.sh`, a scripted Homebrew with realistic sample data, and captures Dashboard, Search, Updates, Settings, Packages, and Services in dark and light themes. Demo mode keeps settings, history, and favorites in a temporary location, so screenshots never show or change your own data.

```bash
Scripts/screenshots.sh dist/screenshots
SHOTS_ONLY="Packages Settings-Light" Scripts/screenshots.sh dist/screenshots
```

The terminal needs the Screen Recording permission. Keep the Mac idle while it runs so each window stays in front.

## Releasing

Releases are universal, signed with a Developer ID, and notarized.

One-time setup:

1. Install a **Developer ID Application** certificate in your keychain.
2. Store notarization credentials:
   ```bash
   xcrun notarytool store-credentials "Brewwery" --team-id <TEAM_ID>
   ```
3. Make sure the Sparkle EdDSA key is in the login keychain under the account `brewwery`, and that its public key matches `SUPublicEDKey` in `Packaging/Info.plist`.

For each release:

1. Update `CFBundleShortVersionString` and `CFBundleVersion` in `Packaging/Info.plist`, and `CHANGELOG.md`.
2. Run:
   ```bash
   Scripts/release.sh --sign "Developer ID Application: …" \
     --site-public "../site/public"
   ```
   The script builds the universal app, signs it inside out with the hardened runtime, notarizes and staples it, wraps it in a signed DMG, notarizes and staples the DMG, and regenerates the Sparkle appcast. With `--site-public` it also copies the DMG to `download/brewwery.dmg` and the appcast to `appcast.xml` in the website.
3. Tag the release and upload `dist/appcast/Brewwery-<version>.dmg` to its GitHub release — the appcast points there.
4. Deploy the website so `https://www.brewwery.com/appcast.xml` and `/download/brewwery.dmg` serve the new files.

Keep a backup of the Sparkle private key. Without it, installed copies cannot receive updates.

## Guidelines

- Homebrew runs only through `HomebrewCommand`: no shell, no free-form arguments, every dynamic value validated in `HomebrewIdentifier`.
- Anything that changes Homebrew needs an explicit confirmation.
- Tests must never reach the real Homebrew unless they are in `BrewweryLiveTests`.
- Icon-only buttons use `IconButton`, so they always have an accessible name.
- Record deliberate behavior changes in `docs/ARCHITECTURE-DECISIONS.md`.
- Do not add telemetry, authentication, cloud sync, or monetization.
